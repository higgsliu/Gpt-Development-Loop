# L1 示例｜局部 Bug 修复

## 场景

某内部工具在空字符串输入时抛出异常。问题只影响单个模块，不改变公共 API，不涉及真实生产写入。

## GPT 判断

```text
RISK=L1
```

原因：

- 单模块局部逻辑
- 无公共 Contract 变化
- 无生产关键状态
- 可以通过直接测试充分证明结果

## Codex Task

```text
CLAIM:
修复 parser 在空字符串输入时抛异常的问题，保持其他输入行为不变。

CONTEXT:
- 已确认异常只发生在空字符串分支。
- 当前函数被内部工具调用。

RISK:
L1

CHANGED_SURFACE:
- parser 空字符串处理
- 对应单元测试

ACCEPTANCE:
1. 空字符串返回既定空结果，不抛异常。
2. 正常字符串解析行为不变。
3. 最小相关测试通过。

CONSTRAINTS:
- 不重构 parser 模块。
- 不修改调用方。
```

## Codex 执行

```text
读取真实代码
→ 最小修改
→ T0
→ T1
→ Git Diff
→ Commit
```

不要求为了形式执行：

- Clean Reproduction
- 完整 GPT Delta Review
- Runtime Acceptance
- Outcome Acceptance

除非实施过程中发现风险实际高于 L1。

## Handoff 示例

```text
STATUS: COMPLETED
CLAIM: 修复 parser 空字符串异常
OUTCOME: 空字符串现在返回空结果，正常输入行为未改变
REPOSITORY: owner/repo
CHANGED_FILES:
- src/parser.py
- tests/test_parser.py
TEST:
- T0: PASS
- T1: PASS
GIT:
- COMMIT: <sha>
SYSTEM_STATE: NO_CHANGE
RISKS: NONE
NEXT: STOP
```

## 为什么这里应该停止

当前 Claim 已经由局部代码变化 + 直接测试充分证明。

继续增加端到端环境、状态文件、完整 Review 流程只会增加治理成本，不增加实质可靠性。
