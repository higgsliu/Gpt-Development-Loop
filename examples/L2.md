# L2 示例｜共享 Contract 修改

## 场景

一个共享鉴权中间件在 Token 过期时错误返回 500。该中间件被多个 API 入口共享，因此虽然修改不大，但会影响公共能力。

## GPT 判断

```text
RISK=L2
```

原因：

- 修改共享基础能力
- 存在多个消费者
- 需要确认公共响应 Contract 未被破坏

## Codex Task

```text
CLAIM:
修复共享鉴权中间件在 Token 过期时返回 500 的问题，并保持现有认证 Contract 兼容。

CONTEXT:
- 已确认异常发生在过期 Token 分支。
- 正常 Token 和缺失 Token 行为当前正确。
- 中间件被多个 API 入口共享。

RISK:
L2

CHANGED_SURFACE:
- 共享鉴权中间件的过期 Token 处理
- 相关 Contract 测试
- 必要消费者回归测试

ACCEPTANCE:
1. 过期 Token 返回既定鉴权错误，不再产生 500。
2. 正常 Token、缺失 Token 行为不变。
3. 主要消费者相关测试通过。

CONSTRAINTS:
- 不重构整个认证系统。
- 不改变公开响应 Schema。
- 不处理其他登录问题。
```

## Codex 执行

```text
真实代码检查
→ 最小实现
→ T0
→ T1
→ 必要 T2
→ Review Snapshot
→ Push Review Branch
→ Handoff
```

固定：

```text
REVIEW_BASE=<base sha>
REVIEW_HEAD=<head sha>
REVIEW_REF=refs/heads/codex/auth-expired-token
GPT_REVIEW_READY=YES
```

## GPT Delta Review

GPT 不依据 Codex 的“测试通过”直接接受，而是实际读取：

```text
REVIEW_BASE..REVIEW_HEAD
```

重点检查：

1. 过期 Token 分支是否真正修复。
2. 公共响应 Schema 是否变化。
3. 正常 Token / 缺失 Token 是否被意外影响。
4. T1 是否直接覆盖根因。
5. 主要消费者是否有必要 T2。

## 可能结论

### ACCEPTED

```text
GPT_REVIEW: ACCEPTED
NEXT: INTEGRATION
```

如果该中间件影响真实 Runtime：

```text
Integration
→ Runtime Acceptance
→ main
→ STOP
```

### REVISION_REQUIRED

例如发现 Codex 修改了公共错误码：

```text
GPT_REVIEW: REVISION_REQUIRED
ISSUE: 公开错误码由 AUTH_EXPIRED 改成 INVALID_TOKEN
WHY_IT_BLOCKS: 改变既有公共 Contract，可能破坏消费者
REQUIRED_CHANGE: 保持现有错误码，只修复 500 分支
NEXT: CODEX_REVISION
```

新 Commit 后生成新的 `REVIEW_HEAD`，重新 Review。

## 核心区别

L2 的重点不是“测试更多”，而是：

> **共享能力修改必须有独立、固定 Git Delta 的 Review 证据。**
